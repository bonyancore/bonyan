# i18n and RTL — how this project works

Stack: Next.js 16 (Cache Components) + next-intl 4. Languages: Arabic (default, RTL) and English (LTR).

## Architecture in one picture

```
URL  /ar/...  or  /en/...            (always prefixed, shareable, cache-friendly)
 │
 ├─ src/proxy.ts          detects locale: URL → NEXT_LOCALE cookie → Accept-Language → default (ar)
 ├─ src/i18n/locales.ts   ONE source of truth: dir, native name, default locale, site time zone
 ├─ src/i18n/routing.ts   next-intl routing (derived from locales.ts)
 ├─ src/i18n/request.ts   per-request config: messages, formats, time zone (locale from next/root-params)
 ├─ src/i18n/navigation.ts  Link / redirect / usePathname / useRouter  ← use THESE, not next/link
 ├─ src/i18n/formats.ts   named number formats (Western digits pinned)
 ├─ src/i18n/dates.ts     ISO dates (2026-10-22), same in every language
 ├─ src/global.ts         makes t("keys"), useLocale() and formats fully typed
 ├─ messages/{ar,en}.json translations (en.json is the type source)
 └─ src/app/[locale]/layout.tsx   the ROOT layout: <html lang dir>, generateStaticParams
```

## Daily rules

1. **No user-visible text in components.** Add the key to BOTH `messages/ar.json` and `messages/en.json`.
2. **Imports:** `Link`, `redirect`, `usePathname`, `useRouter` come from `@/i18n/navigation`.
3. **Logical CSS only:** `ms- me- ps- pe- start- end- text-start border-s rounded-s`. Never `ml- pr- left- text-left`.
4. **Numbers:** `format.number(x, "integer" | "decimal" | "quantity" | "percent")`. Wrap digits in `.num`.
5. **Money:** `<Money value={45000} currency="EGP" />`. Never format currency inside `.num`.
6. **Numeric dates:** `isoDate(d)` / `isoStamp(d)`. Month names: `format.dateTime(d, "long")`.
7. **Plurals:** ICU in the message. Arabic needs `zero/one/two/few/many/other`, see `tasks.dueToday`.
8. **Rich text:** `{placeholders}` take strings/numbers/dates; markup goes through `<tags>` (see `Money`).
9. **Custom Tailwind tokens** (`--text-*`, `--shadow-*`) must be registered in `src/lib/utils.ts`.

## Guards (run `npm run check` before every PR, and in CI)

| Script | Fails when |
| --- | --- |
| `i18n:check` | a key exists in one language but not the other, a value is empty, or ICU arguments differ |
| `lint:rtl` | a physical left/right Tailwind class is used |
| `check:tokens` | a custom font size or shadow is missing from `cn()` |
| `typecheck` | a translation key or number format does not exist |

## Add a language (example: French)

1. `src/i18n/locales.ts`: add `fr: { dir: "ltr", nativeName: "Français", short: "FR" }`.
2. Copy `messages/en.json` to `messages/fr.json` and translate.
3. `npm run check`. Nothing else changes (routing, switcher, proxy and layout all derive from `locales.ts`).

## Known limits and decisions

- **Dates are ISO in numeric form** on purpose. `en` resolves to US order (10/22/2026), which is ambiguous for Egypt/KSA.
- **Time zone** is `Africa/Cairo` for now (Egypt observes DST, KSA does not). Make it a per-project setting when projects exist.
- **Locale switcher keeps the path, not the query string.** Add query preservation when a page needs it (requires a Suspense boundary under Cache Components).
- **Route Handlers and Server Actions** cannot use `next/root-params` yet. Pass the locale explicitly there.
- **Unknown URLs** hit `[locale]/[...rest]` and render the localized 404 after the client resumes (Cache Components streams the shell first).
- **UI primitives:** when you add shadcn/Base UI components that need a direction (menus, popovers, sliders), wrap the app in the library's `DirectionProvider` using `getDirection(locale)`.
- Fonts are self-hosted (see `src/fonts/README.md`).
